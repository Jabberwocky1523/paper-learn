@@S001
摘要
@@S002
KV 缓存能够降低大语言模型（LLM）的服务成本，但不断增长的 KV 缓存占用正日益超出 GPU 和主机内存的容量。因此，人们使用 SSD，以较高的 I/O 带宽扩展 KV 缓存的存储容量。然而，在多轮对话和 LLM 智能体等生产环境工作负载中，KV 缓存的总写入量远超 SSD 容量，使 SSD 寿命从数年缩短至数月。要延长 SSD 寿命，一个自然的办法是根据历史访问模式控制 KV 缓存写入，从而减少写入量。但这会显著降低 KV 缓存命中率，并增加 LLM 服务成本，因为不同注意力类型产生的 KV 缓存可能具有相同的历史访问模式，却具有不同的未来访问模式。我们的洞见是：要在不损害 KV 缓存命中率的情况下减少写入，不仅需要考虑访问模式，还需要考虑 KV 缓存的注意力类型等应用层信息。基于这一观察，我们提出 Gandalf，这是首个具有 SSD 寿命感知能力的 SSD KV 缓存卸载系统。Gandalf 优先将全注意力 KV 缓存准入 SSD，而非其他注意力类型产生的缓存，从而在不牺牲缓存命中率的情况下显著延长 SSD 寿命。评估表明，在多种工作负载轨迹和广泛的硬件容量配置下，Gandalf 平均将 SSD 寿命延长至原来的 7.3 倍，对缓存命中率的影响可以忽略不计。Gandalf 的设计还可扩展到高带宽闪存（HBF）等其他闪存存储。
@@S003
1 引言
@@S004
大语言模型（LLM）在多轮对话和智能体工作流中展现出强大能力，因而得到广泛采用。这些工作负载会积累对话历史、工具输出和中间状态，形成越来越长、且被频繁复用的上下文。然而，如果每一轮都重新计算这些上下文的注意力键值（KV）状态，就会显著增加推理延迟和成本。因此，人们在系统中保存所有 KV 缓存，以避免重新计算并提高缓存命中率 [1, 32]。生产环境工作负载每天会产生数 TB 的 KV 缓存，超过 GPU 和主机内存的容量，因此需要采用容量更大的存储层。NVMe SSD 等闪存存储为这些缓存提供了可扩展且成本效益相对较高的存储层 [29]。
@@S012
这种额外容量也带来了耐久性挑战，因为 SSD 在磨损失效前只能承受有限的写入量 [4]。在生产环境工作负载下，积极准入 KV 缓存可以提高命中率，但也会产生大量写入，在数天至数月内耗尽 SSD 的写入耐久预算。因此，现有生产级系统采用简单的过滤技术来控制 SSD 准入，以减少潜在缓存命中为代价降低写入量。例如，基于频率的方案只有在某个 KV 缓存已展现出 $N$ 次复用后，才将其卸载到 SSD，其中 $N$ 为超参数 [30, 35]。然而，即使采用这种过滤，KV 缓存的总写入量对于实际 SSD 的耐久能力而言仍然过大。由此产生了一个核心问题：**如何在不牺牲 KV 缓存性能收益的前提下延长 SSD 寿命？**
@@S013
关键挑战在于预测 KV 缓存的未来复用情况，以便只选择性保留最有可能被复用的缓存，充分利用 SSD 容量。预测未来很困难，但我们发现，应用特有的属性与复用模式高度相关。我们利用了两项观察：（1）近期的 LLM 越来越多地采用混合架构，将全注意力层与线性注意力层或稀疏注意力层相结合；（2）在多轮对话和智能体工作流这些新兴主流工作负载中，不同注意力层类型产生的 KV 缓存具有显著不同的复用模式。具体而言，线性注意力层和稀疏注意力层的状态，其复用频率低于全注意力层的 KV 缓存。
@@S014
以多轮对话工作负载为例，其复用模式如表 1 所示。每一新轮次开始时，都需要此前整个上下文的全注意力 KV 条目。这一模式在每一新轮次中重复，因此这些 KV 条目会在后续所有轮次中被复用。相比之下，线性注意力层的状态和滑动窗口缓存仅用于生成紧接着的下一轮响应，随后便被丢弃，因此每个状态只复用一次。
@@S015
复用模式的这种异质性启发了注意力类型感知的缓存放置策略。将体积较大、仅使用一次的线性注意力状态写入 SSD，既消耗写入耐久预算和缓存容量，又只能带来很少的缓存命中收益。因此，层类型可以作为实用的放置信号，使我们能够利用 SSD 扩展缓存容量，同时尽量降低耐久损耗。我们提出一种注意力层感知放置策略：将短寿命线性注意力状态缓存在主机内存中，将寿命较长的全注意力 KV 缓存保存在 SSD 上。
@@S016
然而，这种放置策略面临 2 个实际挑战。
@@S017
首先，这种放置策略过于僵化：CPU DRAM 和 SSD 的容量固定，但不同工作负载可能产生不同数量、不同类型的注意力状态。特别是，并发会话较多的工作负载可能产生大量可复用的线性注意力状态，超过可用 DRAM 容量；类似地，长上下文工作负载可能产生大量可复用的全注意力 KV 缓存，超过可用 SSD 容量。我们将其称为“硬件与利用需求失衡”。这种失衡会迫使已饱和的存储层频繁驱逐缓存，即使存储层级中的其他位置仍有空闲容量，从而降低缓存命中率。更糟的是，如果过度利用发生在 SSD 上，由此产生的反复写入会更快消耗其耐久预算，进一步缩短寿命。因此，我们设计了一种容量感知放置策略，根据各层的利用率和压力过滤 SSD 准入，在缓存命中率与 SSD 耐久性之间取得平衡。
@@S018
其次，这种僵化放置会把原本由 DRAM 提供的缓存命中转移至 SSD。由于 SSD 带宽显著低于 DRAM 带宽，这可能损害首 token 延迟（TTFT）。因此，从 SSD 传输体积较大的全注意力 KV 缓存可能增加 TTFT。
@@S019
我们使用离线预知算法（oracle）探索注意力类型感知放置的潜力。该算法倾向于采用我们提出的分层放置方式，并联合优化 SSD 准入与缓存驱逐决策。它揭示了两个相辅相成的设计原则。第一，放置必须适应各层容量，并选择性地将 KV 缓存持久化到 SSD，以保留前缀命中边界。第二，准入和驱逐必须联合优化：准入新缓存既有收益，也有成本。收益来自未来复用，成本则包括写入成本与替换成本——即替换其他缓存条目的代价，而这些被替换条目可能已经兑现、也可能尚未兑现其预期收益。只有当预期复用价值超过写入成本与被驱逐条目价值之和时，SSD 准入才有益。这些原则共同刻画了 SSD 寿命、缓存命中率和 TTFT 之间可达到的最佳权衡。随后，我们将 oracle 的决策提炼为一种在线容量感知策略，根据历史访问模式估计未来复用。
@@S021
**贡献。** 本文的主要贡献如下：
@@S022
（1）我们首次表明，在生产规模、基于 SSD 的 KV 缓存卸载中，SSD 寿命显著低于其出厂保证期限。
@@S023
（2）我们表明，利用应用层信息，即每个 KV 缓存对象对应的注意力类型，可以显著减少写入量并延长 SSD 寿命，同时对 KV 缓存命中率的影响可以忽略不计。
@@S024
（3）我们提出 KV 缓存系统 Gandalf。在广泛的 LLM 和硬件容量配置下，它平均将 SSD 寿命延长至原来的 7.3 倍，对命中率的影响可以忽略不计。
@@S025
尽管本文只在 SSD 上展示了 Gandalf，但该技术可扩展到高带宽闪存（HBF）等其他闪存存储设备。
@@S026
2 研究动机 / 2.1 KV 缓存超出内存容量
@@S027
过去几年，LLM 智能水平和上下文窗口长度的增长，推动了多轮对话和智能体工作流的发展。这类工作负载会持续积累对话历史、中间推理、工具输出和子智能体结果。与单轮请求不同，它们会反复扩展并复用已有前缀，使每个会话的 KV 缓存占用在其整个生命周期中持续增长。因此，跨请求、跨会话保存的 KV 缓存总量正变得极其庞大。
@@S028
长上下文也使缓存未命中的代价越来越高。当某个可复用前缀未被缓存时，服务系统必须在生成响应前，对此前所有 token 执行预填充，重新计算其 KV 状态。在多轮对话、智能体工作流和长文档处理等长上下文工作负载中，这会反复消耗稀缺的 GPU 计算资源，增加 TTFT 和服务成本。因此，人们希望尽量保留更多可复用 KV 状态，实质上是用存储容量换取计算资源。
@@S029
我们分析了两条各持续一天的 SemiAnalysis Claude Code 轨迹 [40]，估计代表性混合模型每天会生成 81–240 TB 的 KV 缓存状态（表 2）。在峰值时，并发活跃的 KV 缓存工作集达到 8.6 TB，超过实际可配置的主机内存容量；配置足够的 CPU DRAM 将带来难以承受的成本。因此，仅靠内存无法保留这些状态以供未来复用。缓存容量必须扩展到 GPU 和主机内存之外、容量更大的本地存储。
@@S031
2.2 为什么不用 HDD 集群？
@@S032
本地 NVMe SSD 是 LLM 服务中扩展内存层级的常见选择 [13, 16, 28, 38, 41, 43]。既然 SSD 的耐久性有限，为什么人们没有改用 HDD？为了使 HDD 足够快，可以让一个 HDD 集群并行执行 I/O。为回答这一问题，我们首先依据制造商规格比较 SSD 与 HDD 的耐久能力。
@@S033

@@S042
2.3 KV 缓存正在迅速耗尽 SSD 寿命
@@S043
我们的分析表明，在前沿模型和智能体工作负载下，即使是 30 TB 企业级 SSD，也可能在不到一年内耗尽额定 TBW。容量较小的企业级 SSD 磨损得更快，2 TB 设备只需数天就可能达到额定 TBW。第 2.2 节讨论过，SSD 磨损是主机写入量与设备级写放大的乘积。我们针对主机写入，减少向 SSD 发出的 KV 缓存写入。
@@S044
分层 KV 缓存通常采用直写或回写卸载。
@@S045
**直写（write-through）** 会立即将每个准入的 KV 状态复制到 SSD，使其在多个存储层中尽可能可用，但会产生大量 SSD 写入。这种复制可在条目被 DRAM 驱逐后继续保留它；然而，如果条目的全部复用都在其仍驻留 DRAM 的短时间内完成，就会浪费 SSD 耐久预算。此时 SSD 副本消耗了写入预算，却未贡献任何缓存命中。
@@S046
**回写（write-back）** 会将从上层存储降级的 KV 状态持久化，而不考虑其预期复用。这种策略仍会把每个被 DRAM 驱逐的状态写入 SSD，其中包括对未来缓存命中几乎没有贡献的状态。
@@S047
**选择性直写（selective write-through）** 使用固定的复用阈值来减少这类流量。例如，NVIDIA Dynamo 仅在块的访问频率达到两次后才进行卸载 [30]。然而，只依赖频率的过滤忽略了状态大小、特定层的复用特征、各层占用情况和剩余写入预算，使得体积较大、寿命较短的状态可能消耗大量耐久预算，却收益甚微。
@@S048
2.4 既有工作如何应对 SSD 耐久性问题？
@@S049
SSD 耐久性长期以来一直是闪存缓存系统关注的问题。Flashcache [11] 和 Google 的 Colossus Flash Cache [51] 等传统系统使用 SSD 加速持久化数据访问。近期研究表明，KV 缓存卸载也给 LLM 服务带来了类似的耐久性挑战 [23, 42]。现有方法可分为三类。
@@S050
**提高物理写入耐久性。** 通过增加硬件，将写入分散到更多 SSD 上，汇总写入预算并降低每个设备的写入速率，可以提高总体写入耐久能力，代价是额外的购置、功耗和维护成本 [19]。一种经典 SSD 耐久性技术称为“放宽数据保持要求”，它通过降低数据保持要求，提高 NAND 可承受的编程／擦除循环次数 [5, 26]。FlashAccel 利用 KV 缓存寿命短的特点，用较短数据保持时间换取更高耐久性 [45]。然而，这两类方法增加的是可用写入预算，并未减少主机侧 KV 缓存写入，而且可能需要额外硬件或设备支持。它们也没有利用 KV 缓存的一项独有属性：可以选择不缓存，而在需要时重新计算。因此，对于持续的 LLM 服务，尤其是多轮对话和智能体工作负载，这些方法仍可能不足。
@@S052
**选择性 KV 缓存准入与驱逐。** 尽管许多现有缓存准入和驱逐策略并非为延长 SSD 寿命而设计，它们仍会选择性过滤 KV 缓存，通过优化缓存利用与复用提高命中率，并间接减少写入。一种方法调度那些所需 KV 缓存已驻留、且能容纳于可用空间中的请求 [52]。LRU-$K$ 仅在 KV 缓存已被访问 $K$ 次后才准入 [31, 35]。DeepSeek-V4.1 将滑动窗口 KV 缓存保留在分布式内存池中，以保证其他 KV 缓存能在持久化存储中保留至少 72 小时 [8]。HotPrefix [22] 和 PrefixShield [46] 利用基于前缀的策略，从 GPU HBM 中驱逐冷 KV 缓存；Workload-Aware [44] 则考虑复用概率、块位置和寿命。LPC [49] 和 SAECache [12] 使用学习方法预测复用。RR-evict [34] 使用轮转驱逐保证会话间公平性，Bidaw [14] 根据会话中此前的响应预测复用距离。另一种方法综合最近访问、频率和基于指数加权移动平均（EWMA）的复用估计，执行预取与驱逐 [43]。MeritKV [17] 在节省的预填充时间减去查找与传输成本、再减去历史未命中的重新计算成本后低于阈值时，对存储后端准入进行门控。然而，这些方法并未显式优化 SSD 耐久性。
@@S053
2.5 SSD 寿命与缓存命中率之间的权衡
@@S054
硬件配置——主机内存大小和 SSD 容量——是固定的，但工作负载需求会随时间显著变化。由于缓存条目被视为具有同质的复用特征，存储层级必须统一处理它们。因此，现有方案需要在 SSD 寿命与缓存命中率之间作出权衡，如图 3 所示。
@@S055
在 SSD 上存储更多 KV 缓存条目，会提高未来请求找到可复用状态的概率，从而提高缓存命中率并降低 TTFT。然而，由此产生的写入量会迅速消耗 SSD 有限的耐久预算。反过来，存储更少条目可减少 SSD 流量并延长设备寿命，但可能丢弃可复用状态，降低命中率并增加 TTFT。因此，当缓存条目具有同质特征时，改善一个目标必然要牺牲另一个目标。要打破这一权衡，必须识别那些消耗 SSD 耐久预算、却对未来缓存复用贡献很小的写入。
@@S057
2.6 关键观察：混合模型具有异质复用模式
@@S058
稠密模型的所有层都使用全注意力。当恢复使用某个缓存上下文时，序列前缀中每个 token 的 KV 条目都会被复用。因此，存储更大比例的前缀可以避免更多重新计算，使 SSD 写入量与缓存命中率之间形成近似一对一的权衡。每一层、每个 token 被准入的 KV 条目都提供相近的复用价值，减少 SSD 写入通常就会牺牲相应的缓存机会。由此形成 SSD 寿命与缓存命中率之间表面上的一对一权衡。
@@S059
混合模型的架构打破了这一权衡：它将全注意力层与线性注意力、滑动窗口注意力等稀疏注意力层相结合。如表 1 所示，不同层类型的缓存状态呈现出显著不均匀的复用模式，线性状态的复用远少于全注意力 KV 缓存。我们观察到，在多轮对话等仅追加的工作负载下，所有前缀 token 的全注意力 KV 缓存都会在后续每一轮被复用，因此其复用次数随对话增长而增加。相比之下，每个稀疏注意力状态通常只使用一次，用于生成紧接着的下一轮，随后便被更新的状态取代。
@@S060
将这些短寿命状态统一写入 SSD 是低效的。直写会立即将其持久化，回写则可能在驱逐时持久化，即使它们很可能只复用一次就被取代。当最新的线性注意力状态可以一直留在 DRAM 中直到下一轮时，其 SSD 副本不会增加缓存命中，却仍消耗 SSD 耐久预算和容量。这类写入还可能驱逐更有复用价值的全注意力 KV 条目，进一步降低缓存效果。
@@S061

3.1 注意力类型感知放置
@@S064
混合模型产生的缓存状态在大小和复用模式上存在显著差异。全注意力层保留每个 token 的 KV 条目，因此缓存随前缀长度增长；线性注意力层则在每个检查点维护固定大小的递归状态。滑动窗口层仅保留最近 $W$ 个 token，因此可以采用与线性注意力层相同的放置策略。各类状态的大小也相差很大。在我们评估的模型中，一个线性注意力状态所占空间，相当于 2k–16k 个 token 的全注意力 KV 条目。然而，只有当各类状态都在同一个前缀边界上可用时，复用才有意义。
@@S065
大小与复用模式的异质性带来 2 个机会：（1）并非所有 KV 状态都需要缓存；（2）可以决定已准入状态应放在哪里。这种异质性产生两个不同的缓存管理决策。首先，准入决定哪些生成状态具有足够的复用价值、值得保留。其次，放置决定每个已准入状态应驻留在哪个存储层。
@@S066
既有工作通过探测复用边界，解决了“应缓存哪些 KV 状态”的问题 [33, 46]。这些机制决定哪些状态应被保留，但不决定已准入状态应驻留在 DRAM 还是 SSD 中。我们的目标是利用 KV 缓存的注意力层类型，为最合适的存储层放置位置提供线索，通过管理缓存放置延长 SSD 寿命。
@@S067
因此，我们将线性状态保留在 DRAM 中，将全注意力 KV 缓存保留在 SSD 中。每轮对话结束时生成的线性状态放入 DRAM，全注意力 KV 缓存则放入 SSD。当某个存储层（DRAM／SSD）空间耗尽时，驱逐该层最近最少使用的缓存。

@@S069

@@S070

3.4 优化
@@S106
每次驱逐都为所有缓存块评分，成本很高：缓存中包含数百万个块，其按概率加权的评分还会随时间变化。Gandalf 利用三项观察来避免这类成本。
@@S107
**第一，只有叶节点可以被丢弃，只有靠近根部的 DRAM 节点可以移动至 SSD。** Gandalf 仅增量维护这两个集合。丢弃一个叶节点，最多会使其父节点成为新的叶节点；移动一个根侧节点，则会使其子节点成为新的移动候选。因此，缓存评分仅在发生缓存压力时，对少量条目重新计算。
@@S108
**第二，公式（7）中的评分随对象变旧而变化，但在同一个请求内保持不变。** Gandalf 为每个存储层的叶节点候选维护一个最小堆，按照概率加权的丢弃评分 $H_d$ 排序。每个新请求只有首次查询时才重建堆，该请求内后续所有驱逐都复用它。新叶节点立即插入，失效条目则在堆顶被惰性移除。
@@S109
**第三，Gandalf 按缓存类型将根侧 DRAM 候选分为线性状态和全注意力 KV。** 在每个大小类别中，预计剩余寿命最长的候选具有最低的 SSD 写入费用。因此，按剩余寿命排序的惰性堆能够找到该候选，无需在请求期间再次为整个类别评分。默认情况下，Gandalf 只比较每个大小类别中寿命最长的一个候选。后续评估将表明，仅比较一个候选不会牺牲性能。另外，一个针对 SSD 叶节点的惰性最小堆用于识别价值最低的 SSD 驱逐对象，从而确定替换成本：当 DRAM 压力触发对象从 DRAM 移动至 SSD、需要驱逐 SSD 对象腾出空间时，使用该成本。建堆之后，每次决策仅检查堆顶，无需对全部缓存对象重新评分或排序。
@@S110
4 实现
@@S111
**验证模拟器。** 我们首先运行 vLLM [18]，将其连接到 RawBlock 模式下的 LMCache [7]，执行一条 Claude Code 轨迹，并附加基于 eBPF 的日志记录器，导出面向存储的访问轨迹。轨迹包括首次运行以来的时间戳、操作类型（读／写）、访问的逻辑块地址（LBA）、大小和页数等列。随后，我们在 FEMU [21] 中重放轨迹，将 SSD 配置为 1 TB、0.3 DWPD、保修期 5 年，以观察 KV 缓存卸载工作负载下的 SSD 寿命，由此发现 KV 缓存正在迅速消耗 SSD 寿命。我们从这一结果得到 SSD 寿命时长，然后构建基于轨迹的模拟器，通过 TBW 估计 SSD 寿命，并用 SSD 仿真器得到的寿命进行验证。在真实硬件上实现前，需要先通过模拟器运行所有实验，因为直接实验确实会使 SSD 耗尽寿命。所有技术确认后，我们将其迁移至实际生产系统，使用 LMCache [7] 作为 vLLM [18] 推理引擎的后端。
@@S112
**SSD 寿命估计。** 具体来说，在使用仿真器进行小规模寿命验证之后，我们通过 TBW（总写入字节数）估计 SSD 寿命。每重放一条轨迹，便可得到 SSD 总写入量。假设生产系统反复重放这条轨迹，就可得到每日总写入量，再用 TBW 除以每日总写入量来估计 SSD 寿命。
@@S113
**层间传输。** 层间传输假设采用两跳方式，以 CPU 作为暂存缓冲。SSD 命中的数据必须先传输到 CPU DRAM，受 SSD 读取带宽和 SSD 传输带宽约束；CPU DRAM 命中的数据再传输到 GPU 内存，受 CPU 至 GPU 的 PCIe 带宽约束。
@@S114
**硬件规格。** 模拟器对影响 SSD、CPU DRAM 与 GPU HBM 之间传输的系统硬件规格进行建模。我们假设某一具体 GPU 型号，检查其每秒 token 吞吐量，并将每个生成的 KV 缓存直接存入 LMCache [7] 等 KV 缓存存储系统。SSD 模型支持指定 DWPD（每日整盘写入次数）和容量。但在评估中，我们假设 5 年内支持 1 DWPD，这是企业级 SSD 的常见规格。我们通过 FIO [2] 测量 SSD 读取和传输带宽，随后改变 SSD 容量进行评估。
@@S115
**已知局限。** 模拟器假设写放大系数（WAF）为 1，因为它没有建模 SSD 内部的垃圾回收、磨损均衡，以及其他可能影响寿命的操作。因此，对于 Gandalf 和所有基线，模拟器都可能高估 SSD 寿命。不过，原文认为 WAF 与较高写入速率有关，因此通过 Gandalf 降低写入量，仍可以降低 WAF 并改善 SSD 寿命。
@@S116

@@S140

5.6 收益来自哪里？
@@S148
**避免将不再复用的线性状态写入 SSD。** Gandalf 避免向 SSD 写入不会被多次复用的线性状态，例如多轮对话每一轮结束时的状态。图 10 在 ClaudeCode、Qwen3.5-27B、100 GB DRAM 和 1 TB SSD 下，展示了随时间变化、至少贡献一次缓存命中的 SSD 写入所占比例，对比 Gandalf 与 LRU-K。在整个轨迹中，无论全注意力 KV 还是线性状态，Gandalf 的 SSD 写入中最终被命中的比例均高于 $K=1$ 的 LRU-K。
@@S149
$K=1$ 的 LRU-K 向 SSD 写入 120.6k 个线性状态，其中只有 21% 曾在 SSD 上被命中：43% 此后再未被请求，45% 在移动到 SSD 前就已经在 DRAM 中完成了唯一一次命中，即某轮状态已经被下一轮复用。增大 $K$ 不能解决这一问题。LRU-K [35] 对每个对象统计引用次数，这可以刻画跨请求持续存在对象的热度，例如生成式推荐中某个用户的 KV 缓存。但线性状态每一轮都会被取代，最多大约被引用两次，因此只有在唯一一次复用结束后才达到 $K=2$ 次引用：LRU-K 会丢弃在下一轮到达前就离开 DRAM 的状态，却写入那些已经被下一轮复用过的状态。当 $K=2$ 时，LRU-K 写入的线性状态减少至原来的 1/1.9，为 62.6k 个，但其中 90% 在写入前已经被命中过，58% 此后再未被请求，仅 13% 在 SSD 上被命中；同时，未命中率从 0.1 升至 0.14。Gandalf 则根据状态未来是否还会复用作决策，而非依据此前被引用的次数：相比 $K=1$ 的 LRU-K，它写入的线性状态减少至 1/8.8，其中 57% 在 SSD 上被命中。
@@S151
当 SSD 已满时，LRU-K 的 SSD 准入变得更严格，因此缓存命中率下降。Gandalf 则始终维持较高的缓存命中率。
@@S152
**避免将很少复用的全注意力 KV 写入 SSD。** 我们还过滤掉未来不太可能复用的条目，例如对话或会话末尾的条目，提高已写入 SSD 的全注意力 KV 缓存条目的复用程度。Gandalf 写入的全注意力 KV 块比 $K=1$ 的 LRU-K 少 33%，分别为 21.5M 和 32.1M；其中 61% 在 SSD 上被命中，而 LRU-K 为 50%。LRU-K 写入的块中，9.6% 此后再未被请求；Gandalf 为 5.3%，因此 Gandalf 写入的此类块减少至原来的 1/2.7，分别为 1.1M 和 3.1M。尽管写入块更少，Gandalf 从 SSD 提供的全注意力命中却多 18%，分别为 265M 和 225M，即每个写入块贡献 12.3 次命中，而 LRU-K 为 7.0 次。综合来看，Gandalf 向 SSD 写入 92 TB，而非 153 TB，在未命中率相近的情况下（0.099 对 0.098），将 SSD 寿命延长至 1.7 倍（98 天对 59 天）。
@@S153
**注意力类型感知放置。** Gandalf 将线性状态放在 DRAM，将全注意力 KV 放在 SSD。图 11 在与上述相同的设置下，对比 Gandalf 与 $K=1$ 的 LRU-K，展示各类缓存命中由哪一层提供。Gandalf 的全注意力 KV 命中有 87% 来自 SSD，线性状态命中有 90% 来自 DRAM。LRU-K 不区分对象类型，只按最近访问情况放置：其全注意力 KV 命中有 74% 来自 SSD，线性状态命中仅有 67% 来自 DRAM，因为其 DRAM 还保存了 Gandalf 会移动到 SSD 的全注意力 KV。为了从 SSD 提供其余 33% 的线性状态命中（27.0k 次），LRU-K 向 SSD 写入 120.6k 个线性状态，每次命中对应 4.5 次写入。Gandalf 则以 13.7k 次写入提供 8.0k 次 SSD 线性状态命中，每次命中对应 1.7 次写入。
@@S154
总体而言，Gandalf 的收益来自将注意力类型作为复用能力的代理信号，从而：（1）避免将每轮结束时的线性状态写入 SSD；（2）避免将很少复用的全注意力 KV 写入 SSD；（3）将线性状态放在 DRAM，将全注意力 KV 放在 SSD。
@@S155
5.7 与各基线逐一比较
@@S156
图 12 在持续 2 小时的 TraceA、Kimi-K3、100 GB DRAM 和 1 TB SSD 下，分解各策略的 SSD 写入。参数分别为 Gandalf 的 $\alpha=1$、HotPrefix 的 $F=1$、LRU-K 的 $K=3$，以及 Marconi 的 $\alpha=0$。
@@S158
**回写基线（LRU、Workload-aware、Marconi）。** 这些策略将每个被 DRAM 驱逐的对象写入 SSD：它们决定驱逐哪个对象，却不决定将其移动至 SSD 还是丢弃。线性状态占其写入字节数的 96%，但写入的线性状态中仅 1.6–8.5% 曾在 SSD 上被命中，LRU 的线性状态有 57% 此后再未被请求。Gandalf 仅写入 25 个线性状态，而 LRU 写入 90k 个；全注意力写入字节数则减少至 1/3.2，分别为 0.53 TB 和 1.70 TB。总计，Gandalf 的写入量减少至 LRU 的 1/73（0.58 TB 对 42.2 TB），SSD 寿命达到 73 倍（253 天对 3.5 天）。Workload-aware 和 Marconi 只改变驱逐对象的选择；Marconi 写入量与 LRU 相近（42.7 TB，3.4 天），Workload-aware 则写入其 1.5 倍（63.5 TB，2.3 天）。在 $\alpha=1$ 时，Gandalf 的未命中率高于 LRU，分别为 0.818 和 0.697，详见下文。在 $\alpha=0$ 时，Gandalf 具有所有策略中最低的未命中率 0.603，SSD 寿命仍为 LRU 的 1.4 倍（4.95 天对 3.46 天），因为写入数据得到了更多读取：其 SSD 提供的全注意力命中为 1.8 倍（2.04M 对 1.14M），线性状态命中为 2.2 倍（38.9k 对 18.0k）。
@@S159
**MeritKV。** 只有当对象节省的预填充代价超过预期复用延迟与写入成本之和时，MeritKV 才将其准入 SSD；但为了学习复用情况，它会无条件准入每个对象的前三次请求。大多数线性状态在该估计生效前就已写入：它写入的线性状态中，97% 在写入前从未被命中。它仍写入 36.1 TB，SSD 寿命为 4.0 天，线性状态写入中仅 5.6% 在 SSD 上被命中，块未命中率为 0.807。
@@S160
**HotPrefix。** DRAM 有空间时，HotPrefix 只有在某个前缀已被请求至少 $F$ 次后才将其准入 DRAM；否则，只有当其频率与最近访问时钟的乘积超过 DRAM 中最冷条目时才准入。被拒绝的前缀会被丢弃，而非写入 SSD。这将写入量降至 4.4 TB，为 LRU 的 1/9.6，SSD 寿命为 33 天。然而，这一过滤器无法区分会被复用的线性状态与其他状态：它写入的线性状态中，97% 此前从未被命中，51% 此后再未被请求，只有 17% 在 SSD 上被命中。被丢弃的前缀会造成未命中，因此其未命中率为 0.802；Gandalf 在 $\alpha=1$ 时，未命中率高出 0.016，但寿命达到其 7.6 倍。当 $F=10$ 时，HotPrefix 写入 0.38 TB、寿命达 388 天，但块未命中率为 0.839。
@@S161
**LRU-K。** LRU-K 仅在对象被引用 $K$ 次后将其写入 SSD。当 $K=3$ 时，它写入 6.8 TB，为 LRU 的 1/6.2，写入的线性状态有 31% 在 SSD 上被命中，而 LRU 为 7.9%。被拒绝的对象会被丢弃，因此其未命中率升至 0.750，SSD 寿命为 21.5 天；Gandalf 在 $\alpha=1$ 时，未命中率高出 0.068，但寿命达到其 11.8 倍。
@@S163
**Gandalf 在何处牺牲命中。** 在 TraceA 上，$\alpha=1$ 时 Gandalf 的未命中率高于 LRU，分别为 0.818 和 0.697。由于仅写入 25 个线性状态，一旦某个对话的线性状态已离开 DRAM，就必须从头重新计算，该对话的全注意力 KV 也无法使用：Gandalf 提供 19.5k 次线性状态命中，而 LRU 为 42.4k 次；全注意力命中分别为 1.11M 和 1.91M。作为交换，其 SSD 寿命达到 73 倍。较小的 $\alpha$ 可用较短寿命换回这些命中（第 5.4 节）。
@@S164
5.8 缓存加载延迟受到多大影响？
@@S165
我们将请求的缓存加载延迟近似为两个时间的较大值：将已缓存 KV 传输到 GPU HBM 的时间，以及重新计算未命中 token 的时间，因为两者可以重叠。传输以 DRAM 为暂存缓冲：先将 SSD 上的 KV 读入 DRAM（10 GB/s），再将每个已缓存字节发送至 GPU HBM（50 GB/s）；重新计算速率为 60k tokens/s。图 13 在 ClaudeCode、Kimi-K3、100 GB DRAM 和 1 TB SSD 下，展示平均缓存加载延迟与 SSD 寿命的关系。加载延迟最低的基线 Marconi（$\alpha=0$）与 LRU 均为 0.66 s，SSD 寿命为 4 个月。Gandalf（$\alpha=1$）的寿命达到其 4.2 倍，为 17.0 个月，加载延迟为 0.78 s，高出 0.12 s。它有更多命中来自比 DRAM 慢的 SSD，且未命中率高出约 0.01（0.056 对 0.045），因此需重新计算略多的 token。在相近加载延迟下，Gandalf 的寿命为 $K=2$ 的 LRU-K 的 3.7 倍（21.2 对 5.7 个月，0.79 对 0.81 s）；当 $\alpha=64$ 时，寿命为 $K=3$ 的 LRU-K 的 5.3 倍，而且加载仍更快（38.6 对 7.3 个月，0.91 对 0.93 s）。
@@S166
然而，更多重新计算并不总是更差。每次写入都会磨损 SSD，相当于消耗其购置价格的一部分，因此请求成本是重新计算未命中 token 的 GPU 成本，加上分摊的 SSD 价格。图 14 为每个策略选取成本最低的超参数，展示平均请求成本。SSD 磨损占 LRU、Marconi 和 LRU-K 成本的 66–86%；最便宜的基线是 $K=2$ 的 LRU-K，每 1k 个请求花费 0.74 美元。Gandalf（$\alpha=1$）每 1k 个请求花费 0.30 美元，成本降至约 1/2.5：其重新计算成本高于 LRU 和 Marconi（每 1k 个请求 0.13 美元，对比 0.11 美元），但 SSD 磨损成本低至任一基线的约 1/3.0（0.16 美元，对比 0.49–0.73 美元）。
@@S168
因此，当 SSD 写入成本较高时，Gandalf 可能选择重新计算更多 token，因为推理成本节省不仅涉及 GPU 这一硬件资源，也涉及 SSD。
@@S169
5.9 优化不会对性能产生负面影响
@@S170
为了降低每次决策的成本，移动门控（第 3.4 节）对每种槽位大小，仅检查寿命最长的 DRAM 条目作为移入 SSD 的候选。当该条目的评分低于写入费用时，就阻止移动，即使同样大小的其他条目可能值得写入。为衡量这一做法的代价，我们在 Kimi-K3、100 GB DRAM、1 TB SSD 和 $\alpha=1$ 下，让移动门控对每种槽位大小最多检查 64 个候选。检查更多候选并未降低 Gandalf 的未命中率：无论候选数多少，TraceA 始终为 0.823，AIPerf 始终为 0.036。在 TraceA 上，额外候选只会移动此后不再读取的条目，使 SSD 写入量增加 1.4%（501 GiB 增至 508 GiB），SSD 寿命从 271 天缩短至 268 天；在 AIPerf 上，第一个候选从未被阻止移动，因此结果完全相同。所以，每种槽位大小仅检查一个候选并未损失命中。
@@S171
6 相关工作
@@S172
**分层 KV 缓存系统。** CachedAttention、FlashGen、LMCache 和 Mooncake 使用主机 DRAM、SSD 或分布式存储扩展 GPU 内存 [7, 13, 16, 36]，TENURE 和其他放置研究则决定 KV 缓存应驻留在哪一层 [28, 43]。InfiniGen 与 Tutti 通过选择性获取和由 GPU 发起的 SSD I/O，降低下层访问开销 [20, 37]。这些系统主要优化容量、延迟或吞吐量，而非 SSD 耐久性。
@@S173
**KV 准入、驱逐与压缩。** 既有策略根据前缀结构、最近访问、频率、语义、排队需求或工作负载历史来预测复用 [12, 22, 33, 34, 44, 46, 48, 49]。MeritKV、Bidaw、LRU-K 和 NVIDIA KVBM 进一步考虑复用效用、存储成本或写入感知 [14, 17, 30, 35]。与其正交的技术通过 token 驱逐、量化或模型级 KV 压缩缩小占用 [8, 25, 53]。这些技术大多没有结合注意力类型带来的复用异质性与显式耐久成本，联合管理 DRAM 放置、SSD 准入和 SSD 驱逐。
@@S174
**闪存感知缓存与存储。** 通用闪存缓存通过准入过滤和写入速率约束控制磨损 [10, 47, 51]；离线研究则扩展 Bélady 式分析，将闪存擦除纳入考虑 [6]。设备级和接口级技术通过数据保持管理、流放置和缓存感知回收来减少物理写入 [24, 26, 27, 39]。面向 LLM 服务，HiFC、FlashAccel 和 HBFlex 优化闪存数据路径、回写与回收 [15, 45, 54]。这些机制与 Gandalf 互补，因为它们没有使用注意力语义来衡量单个 KV 状态的价值。
@@S175
**寿命感知 KV 放置。** 最相关的工作 Lachesis 根据智能体执行框架推断的寿命，在 HBM 与高带宽闪存之间放置智能体 KV 片段 [50]。Gandalf 则面向主机 DRAM 与 SSD，无需执行框架特定信息，即可从混合注意力语义推导复用差异，并联合考虑容量、重新计算收益和 SSD 写入成本。
@@S176
7 结论
@@S177
本文提出 Gandalf，这是一种基于 SSD 的 KV 缓存卸载系统，使用每个 KV 缓存对象对应的注意力类型来预测未来复用的可能性。Gandalf 将短寿命线性注意力状态保留在 DRAM，将复用潜力较高的全注意力 KV 缓存卸载到 SSD。其放置策略权衡每次 SSD 写入带来的预期缓存命中与由此产生的设备磨损。通过同时依据复用潜力和磨损成本过滤写入，Gandalf 在维持缓存命中率的同时延长 SSD 寿命。在多种混合模型和硬件容量下，相较最佳基线，Gandalf 将 SSD 寿命延长至 2–7.3 倍。随着 KV 缓存继续超出可用内存容量，我们希望 Gandalf 能推动未来 KV 缓存系统既考虑 SSD 卸载的性能收益，也考虑每次写入带来的磨损。将 Gandalf 扩展至其他闪存存储类型留作未来工作。
